# Migrate the Go module from `src/` to the repo root (dn-tool)

## Goal and rationale

The Go module for this repository declares module path
`github.com/andreswebs/dn-tool` (see `go.mod`, currently `go 1.26.5`), but the
`go.mod` file lives under `src/`. The Go toolchain and the module proxy map a
module path to the `go.mod` at the repository root, so as published this module
is unreachable through the proxy:

- `go install github.com/andreswebs/dn-tool@latest` fails.
- `pkg.go.dev`, `govulncheck`, and Dependabot cannot resolve the module.

Moving the module contents from `src/` up to the repository root fixes
distribution with zero import-path changes, because the declared module path
already omits `src`. No `.go` file edits are required: imports such as
`github.com/andreswebs/dn-tool/internal/version` continue to resolve unchanged.

This repository has the largest integration surface in the fleet: besides the
Makefile and GitHub workflows, it carries Docker packaging (`Dockerfile`,
`.dockerignore`, `compose.yaml`) and Nix packaging (`flake.nix`, `flake.lock`,
`nix/package.nix`, `nix/overlay.nix`, `nix/module.nix`). All of those must be
updated or verified.

Committing and tagging are left to the repository owner. This plan describes
file changes and verification only. Do not create git commits or tags.


## Step 1: Move the module contents up one level

Run from the repository root (the directory that contains `Makefile` and
`src/`). Using `git mv` preserves history and stages the rename:

```sh
git mv src/go.mod        go.mod
git mv src/go.sum        go.sum
git mv src/.golangci.yml .golangci.yml
git mv src/cmd           cmd
git mv src/internal      internal
rmdir src
```

`.golangci.yml` is a dotfile, so a glob such as `git mv src/* .` would miss it;
move it explicitly as shown. After `rmdir src`, confirm the directory is gone
and nothing was left behind:

```sh
test ! -e src && echo "src removed"
ls -a   # expect go.mod, go.sum, .golangci.yml, cmd/, internal/ at the root
```

No `.go` file edits are needed. Verify imports still resolve after the later
Makefile change with `make validate`.

## Step 2: Makefile

File: `Makefile`. Only one line changes. Line 2 currently reads:

```make
SRC_DIR     := $(CURDIR)/src
```

Change it to:

```make
SRC_DIR     := $(CURDIR)
```

This is the minimal, lowest-risk change: every `cd $(SRC_DIR) &&` prefix in the
recipe (lines 29, 33, 69, 72, 75, 78, 81, 84, 87, 90) then resolves to the
repository root, which is where `go.mod` now lives, and all targets keep
working unmodified. `CMD_DIR := ./cmd/dn-tool` (line 5) and the `LDFLAGS`
module path (line 7,
`-X github.com/andreswebs/dn-tool/internal/version.Override=...`) are unchanged,
since the module path does not change.

Optional cleaner end state (not required): drop the `SRC_DIR` variable and
remove every `cd $(SRC_DIR) &&` prefix so the Go commands run directly from
`$(CURDIR)`. That is a larger diff across ten lines; prefer the one-line change
above unless a fleet-wide Makefile cleanup is being done in the same pass.

## Step 3: GitHub workflows

### `.github/workflows/ci.yml`


### `.github/workflows/release.yml`

Lines 25-26 are identical to the CI block above; apply the same change:

```yaml
          go-version-file: go.mod
          cache-dependency-path: go.sum
```

Line 52, the SBOM generation step (`anchore/sbom-action`), currently:

```yaml
        with:
          path: src
```

Change to:

```yaml
        with:
          path: .
```

SBOM scope decision (resolves the fleet OPEN question for this repo): with
`path: .`, Syft scans the whole repository root. The release job runs
`make dist` before the SBOM step, so at scan time `dist/` holds the built
archives and `bin/` may hold binaries; `docs/` and `nix/` are also present.
The SBOM should describe the released software's Go dependency graph (derived
by Syft's golang cataloger from `go.mod`/`go.sum`), not the docs tree or the
packaged archives. Add a Syft config file at the repository root named
`.syft.yaml` so Syft (invoked by `sbom-action`) excludes the non-source trees:

```yaml
exclude:
  - ./dist
  - ./bin
  - ./docs
  - ./nix
  - ./.github
  - ./result
```

Syft automatically loads `.syft.yaml` from the working directory, so no extra
wiring is needed in the workflow beyond `path: .`. Keep the existing
`SYFT_SOURCE_NAME: dn-tool` and `SYFT_SOURCE_VERSION` env vars unchanged; they
name the SBOM root package explicitly and are independent of the scan path.

## Step 4: Dockerfile

File: `Dockerfile`. The build stage currently copies only the `src/` subtree
(lines 5-8):

```dockerfile
WORKDIR /build
COPY src/go.mod .
COPY src/go.sum .
RUN go mod download
COPY src/ ./
```

After the module moves to the root, rewrite these to a narrow, cache-friendly
copy that brings in only the Go module files (recommended):

```dockerfile
WORKDIR /build
COPY go.mod go.sum ./
RUN go mod download
COPY cmd/ ./cmd/
COPY internal/ ./internal/
```

Keeping `COPY go.mod go.sum ./` before `RUN go mod download` preserves the
existing Docker layer cache behavior (dependency download is re-run only when
`go.mod`/`go.sum` change). Copying only `cmd/` and `internal/` keeps the build
context minimal and avoids pulling `docs/`, `dist/`, `nix/`, or `.github/` into
the image regardless of `.dockerignore` state. The build command on lines
14-18 (`go build ... -o dn-tool ./cmd/dn-tool`) is unchanged.

Alternative (matches the fleet draft's phrasing) if a single wildcard copy is
preferred:

```dockerfile
WORKDIR /build
COPY go.mod go.sum ./
RUN go mod download
COPY . ./
```

If you choose `COPY . ./`, the build context widens to the whole repository
root, so `.dockerignore` must exclude everything that is not needed to build
(see Step 5). The narrow copy above is preferred precisely because it does not
depend on `.dockerignore` being exhaustive.

## Step 7: Nix packaging

### `nix/package.nix`

This file lives in the `nix/` subdirectory, so its `src` path is relative to
`nix/`. Line 11 currently:

```nix
  src = ../src;
```

`../src` resolves to `<repo-root>/src`. After the move, the module is at the
repository root, which from `nix/` is `../.`. A bare `../.` works but takes the
entire repository as the derivation source, so any change to `docs/`,
`README.md`, `AGENTS.md`, or tickets would change the source hash and force an
unnecessary rebuild. Filter the source set to just the Go module inputs using
`lib.fileset` (recommended; resolves the fleet OPEN question for this repo):

```nix
  src = lib.fileset.toSource {
    root = ../.;
    fileset = lib.fileset.unions [
      ../go.mod
      ../go.sum
      ../cmd
      ../internal
    ];
  };
```

`lib` is already a function argument of `package.nix` (line 2), so no new input
is needed. This includes only the files that affect the build, so documentation
and ticket changes no longer trigger Nix rebuilds. `.golangci.yml` is
intentionally omitted because the Nix build's `checkPhase` runs `go test`, not
the linter.

If you prefer the smallest possible diff over rebuild hygiene, `src = ../.;` is
acceptable as a first step, but `lib.fileset` is the recommended end state and
is what this plan adopts.

`vendorHash` (line 12,
`sha256-3E79DpWwCqn+oKM0Y3TkV0Hx1AhwQmXIPuUoTQQQvHU=`) should not change,
because it is computed from `go.mod` and `go.sum`, whose contents are identical
after the move. It must still be confirmed empirically with `nix build` (Step
9). If `nix build` reports a `vendorHash` mismatch, replace the value with the
`got:` hash from the error and rebuild.

The `meta` block, `ldflags` (module path
`github.com/andreswebs/dn-tool/internal/version.Override`), and
`env.CGO_ENABLED` are unchanged.

## Rollback

Because the move is done with `git mv` and the edits are localized, rollback is
a clean `git restore`/`git reset` of the staged changes (or discarding the
branch) before any commit. Nothing outside the working tree is mutated: no tags
are created, the module proxy has no cached version of this path yet, and the
Nix store entries from verification are harmless. If a tag was already pushed
and needs undoing, that is the repository owner's call; nothing in this plan
requires retracting old tags, since they were never resolvable through the
proxy.
